- `ModelMetadata` — provider-agnostic model metadata (`app/providers/model_metadata.py`); `LMStudioProvider` now reads LM Studio's native `/api/v0/models` API (real vision/embedding type, tool-use capability, quantization, loaded state, context length), with graceful fallback to the original `/v1/models` call when unavailable (ADR-0013)
- `docs/adr/ADR-0013-provider-metadata-grounding.md`
- `POST /v1/chat/completions` and `GET /v1/models` — OpenAI-compatible execution endpoints. Any OpenAI-compatible client (Continue, Cline, Cursor, Open WebUI) can now point its base URL at LAIR instead of LM Studio directly and get automatic routing for free (ADR-0014)
- Streaming support (Milestone 6.1) — `stream: true` now streams real Server-Sent Events instead of returning `400`, added after real dogfooding with Cline showed non-streaming was a hard blocker for that client. `BaseProvider.stream_complete()` (concrete default: falls back to `complete()` as one simulated chunk; `LMStudioProvider` overrides it with real token-by-token SSE parsing), `execution.runtime.stream_execute()` (mirrors `execute()`'s never-raises contract via a terminal error event), new `ChatCompletionChunk`/`ChatCompletionChunkChoice`/`ChatCompletionChunkDelta` schemas. A mid-stream provider failure surfaces as a visible `[LAIR error: ...]` message in the stream (the only channel left once headers are sent) while still persisting `execution_outcome.success = False` server-side (ADR-0014 update)
- `app/execution/` package: `Conversation`/`ChatMessage` (request-scoped, stateless value objects parsed from the incoming `messages[]` array — no server-side session state, matching how every target client already resends full history per request), `ExecutionOutcome`, and `runtime.execute()` (invokes the routed provider, translates `CompletionResult` into an `ExecutionOutcome`, never raises)
- `DecisionRecord.execution_outcome` — populated for executed (chat) requests, `None` for decide-only (`/route`) requests; the first real-traffic data available to a future Learning Engine, distinct from benchmark data
- `CompletionResult.prompt_tokens` / `.finish_reason` — populated from data LM Studio's response already contained but the code previously discarded
- `docs/adr/ADR-0014-execution-runtime-boundary.md`
- **Provenance-tagged routing explanations (I-13).** `ScoreFactor` (`app/routing/provenance.py`, `app/routing/score_breakdown.py`) — every scoring factor now carries a `Provenance` tag (`MEASURED` / `COMMUNITY` / `DECLARED` / `HEURISTIC` / `MEMORY`) alongside its human-readable reason. `ScoreBreakdown.reasons` becomes a computed view projected from the tagged `factors` list rather than a manually-appended list, so no factor can be emitted untagged.
- **Savings Dashboard & Cost Transparency (I-01).** `app/costs/` — `PricingTable` (`configs/cloud_pricing.yaml`, explicit model→class mapping with a parameter-count size heuristic as fallback), `CostCalculator`, `SavingsLedger` (JSON-backed running totals, mirrors `KnowledgeBase`/`DecisionRepository`'s pattern). `GET /v1/lair/savings` returns day/month/lifetime totals; every `/v1/chat/completions` response (streaming and non-streaming) now includes `lair_meta.model_used` / `lair_meta.estimated_savings_usd` (`null` when a model has no price-class mapping, never guessed).
- **Single-Slot Scheduler: TTL by model role (I-05).** `app/execution/ttl_policy.py` — `TtlPolicy` sets LM Studio's per-request `ttl` field based on estimated model size (long TTL for small/generalist models worth keeping warm, short TTL for large specialists), threaded through `BaseProvider.complete()`/`stream_complete()` and `execution.runtime.execute()`/`stream_execute()`. The sticky "loaded" bonus this pairs with already shipped in Milestone 6 (`ModelScorer.loaded_bonus_score`, DF-007); `scripts/simulate_scheduler_swaps.py` demonstrates it reduces swap count on a simulated mixed workload. Queueing/batching and speculative-decoding draft-model pairing remain deferred to a later pass at I-05.
- **Hardware-aware onboarding: `lair doctor` + tiered portfolios (I-02).** New `lair/` CLI package (`python -m lair doctor [--init]`). `app/hardware/tier.py`/`gpu_detector.py`/`doctor.py` profile RAM (psutil), GPU (best-effort `nvidia-smi` parsing / Apple Silicon unified-memory detection, deliberately not used on the live routing hot path), and environment health (Python version, LM Studio reachability, port availability), assigning one of four tiers (ENTRY/STANDARD/ENTHUSIAST/CPU_ONLY). `app/registry/portfolio.py` + `configs/portfolios/{tier}.yaml` hold the recommended model set per tier; `--init` saves the pick as `configs/active_portfolio.yaml`, LAIR's one-command registry initialization. Never auto-downloads -- prints LM Studio search terms only.
- **Quantization-aware registry, scoring, and explanations (I-03, ADR-0016).** `ModelMetadata` gains `is_moe`/`active_params_b` (heuristic, from the model id's `-A<n>B` suffix). `ModelScorer` gains a `quant_fit` explanation factor naming the chosen quant and estimated-vs-free RAM, with a tie-breaking bonus (`RoutingPolicy.quant_efficiency_weight`) for memory-efficient quants (Q2/Q3/Q4) among candidates that already passed the existing hard memory-fit filter (ADR-0012) -- never overrides it. KV-cache-aware memory fit is explicitly deferred to I-17 per the plan's own sequencing.
- **One-command IDE integration: `lair install` (I-14).** `app/integrations/` -- `ClientInstaller` ABC + `ContinueInstaller`, writing/restoring `~/.continue/config.json`'s `models` array with correct backup semantics (a pre-existing config is backed up and restored; a config LAIR created from nothing is removed on uninstall, never fabricated as a "restore"). Cline/Cursor/Windsurf/Zed are listed as planned, not guessed at -- their config schemas aren't verified stable enough to auto-write.
- **Language-aware routing (I-10).** `app/routing/language.py` detects the request's language locally (`langdetect`, deterministic seeding, prompts under 15 chars treated as undetectable rather than guessed). `app/registry/language_strengths.py` + `configs/language_strengths.yaml` declare each model's documented multilingual support by id substring; `ModelScorer` gains a `language_fit` factor (`RoutingPolicy.language_match_weight`) so a request in Spanish, Arabic, Hindi, etc. is scored toward the model declared strongest in that language. Toggleable via `Settings.ENABLE_LANGUAGE_ROUTING`.
- **Task Complexity Triage, rules phase (I-04).** `app/routing/complexity.py` — `ComplexityTriage` rates each request 1-5 from zero-cost signals (prompt length, code-block presence, hard-task keywords, conversation depth via the new `Task.conversation_turns`). Runs between capability extraction and candidate discovery in `RoutingEngine.route()`; a complexity ≥ `RoutingPolicy.complexity_reasoning_threshold` (default 4) adds a scored, explained bonus for REASONING-capable candidates only (one-sided by design -- easy requests get no penalty against any model). Persisted on `DecisionRecord.complexity` for a future Learning Engine to calibrate against. Toggleable via `Settings.ENABLE_COMPLEXITY_TRIAGE` (default on); disabled reproduces pre-I-04 routing exactly.
- **Exact-match response cache (I-07 Phase 1).** `app/cache/response_cache.py` — serves a prior answer at zero token/GPU cost when a request's *entire* conversation matches a past one exactly. Off by default (`Settings.ENABLE_RESPONSE_CACHE`), TTL + max-entries configurable, per-request opt-out (`ChatCompletionRequest.lair_no_cache`). Non-streaming only. Embedding-based near-match similarity (Phase 2) explicitly deferred -- the plan's own design notes sequence "exact-match tier first."
- **Model-assisted complexity classification (I-04 Phase 2).** `app/routing/complexity_classifier.py` — `ModelAssistedComplexityClassifier` asks a designated fast local model to rate complexity + task type as JSON, cached by prompt hash. Runs at the API layer before routing, never inside `RoutingEngine.route()` (which stays inference-free); passed in as an optional `complexity_override`. Off and unconfigured by default; falls back to Phase 1's rules cleanly on any failure.
- **Context compression for long chats (I-09).** `app/execution/context_compression.py` — once a conversation's estimated token count crosses `Settings.CONTEXT_COMPRESSION_THRESHOLD` (default 0.8) of the selected model's context window, older turns are condensed (real summary if a summarizer model is configured, otherwise an explicit truncation marker -- never silent, never fabricated). Most recent turns and all system messages always preserved verbatim.
- **KV-cache-aware memory fit (I-17, ADR-0017).** Extends I-03's weights-only fit check to also account for KV cache at a model's configured context length, closing a gap `docs/DOGFOODING.md` DF-006 already documented live. `ResourceProfile` gains `estimated_kv_cache_gb`/`estimated_total_ram_gb`/`kv_cache_quant_recommended`/`effective_ram_gb`; `filter_by_hardware()` now checks the KV-aware total. Calibrated from Llama-2-7B's real published architecture as a deliberate upper bound. Portfolio files gain a per-tier `kv_cache_recommendation`.
- **Hybrid cloud escalation (I-06, RFC-0001, ADR-0018).** Optional, hard-budget-capped escalation to a configured OpenAI-compatible cloud endpoint (`app/providers/cloud.py`) for requests that genuinely exceed local capability, gated on three independent conditions together (high complexity, low local confidence, budget headroom) via `app/routing/cloud_escalation.py`. `app/costs/budget.py`'s `CloudBudgetLedger` tracks real spend separately from I-01's savings estimate. Off by default; every cloud-routed response marked `lair_meta.routed_to_cloud=true` with a reason.
- **RAG-Lite document pipeline (I-08, ADR-0019).** `POST /v1/lair/documents` ingests a PDF or text file, chunks it (`app/rag/chunking.py`), and embeds each chunk locally via `fastembed` (ONNX Runtime, deliberately not `sentence-transformers`/PyTorch -- a meaningfully lighter dependency for a laptop-accessibility-focused project). `app/rag/store.py`'s `DocumentStore` is JSON-backed, no external vector DB, per the plan's own "keep it lite." `ChatCompletionRequest.lair_document_id` retrieves and injects the chunks most relevant to the latest user message, budget-capped at half the actually-selected model's real context window. Verified end-to-end against a real 105-page synthetic PDF with three distinct sections, each correctly retrieved for its own targeted question using real (not mocked) embeddings. Scanned-page OCR explicitly deferred -- no PDF-rasterization dependency introduced this pass.
- **LAIR Compact Models, Phase 1a (I-19, RFC-0003).** `scripts/compactify/pipeline.py` -- a real, tested tensor-train-matrix (MPO) compression/reconstruction pipeline via `tensorly` (numpy/scipy-backed, no torch; added to `requirements.txt` marked test-only, mirroring `reportlab`'s existing precedent). Validated against a synthetic matrix with known ordinary rank plus an incompressible-random-matrix baseline, with a max-rank sanity check confirming the decomposition math itself is correct (~3e-7 reconstruction error). Honest Phase 1a finding, reported not hidden: naive reshape-based tensorization does not automatically expose a matrix's actual low-rank structure -- achieving CompactifAI-level compression on real transformer weights needs a tensorization scheme deliberately aligned with the model's real structure, named as Phase 1b's concrete next step. `app/registry/compact_models.py`'s `CompactModelCatalogLoader` (ships an empty `configs/compact_models/catalog.json`, mirroring I-12's community-scores pattern) gives Phase 2 somewhere to write real, `MEASURED`-provenance entries once a real model is actually compressed and benchmarked -- not yet done this pass.
- **Streaming-Aware Routing infrastructure (I-16, ADR-0021).** `app/hardware/ssd_benchmark.py`'s real (best-effort) sequential-read benchmark feeds a 0.0-1.0 `streaming_viability` score, computed by `lair doctor` and persisted onto `configs/active_portfolio.yaml` via `lair doctor --init` (same path I-12 uses for hardware tier). `ModelMetadata.streamable` (registry schema change) is heuristically inferred from MoE-ness (`detect_streamable()`) per the plan's own "MoE is the priority streamable class" reasoning. `filter_by_hardware()` gains an opt-in allowance (`Settings.ENABLE_STREAMING_ROUTING`, off by default) admitting an oversized-but-streamable model only when viability and a heuristic latency-multiplier estimate both clear configured bars (`STREAMING_MIN_VIABILITY`, `STREAMING_MAX_LATENCY_MULTIPLIER`); `ModelScorer` labels such a pick with the estimated slowdown, never boosts its score. Honestly scoped: no llama.cpp-direct provider exists in this codebase yet (LM Studio doesn't expose mmap/streaming knobs), so the actual streaming execution path -- and the plan's "one oversized MoE model demonstrably answers via streaming" acceptance criterion -- is deferred to the future Multi-Provider milestone; this pass ships the hardware signal and registry schema real, tested, and ready for that provider to plug into.
- **Battery & Thermal Awareness (I-15).** `app/hardware/power.py`'s `read_power_state()` reads this machine's battery state cross-platform via `psutil.sensors_battery()` (always "not on battery" on a desktop or any platform/psutil build without battery support -- the safe, no-bias default, never a guess). `ModelScorer` gains a `battery_awareness` factor (`RoutingPolicy.battery_efficiency_weight`, provenance `HEURISTIC`): on battery power, a bonus for models estimated at or under the same "generalist" RAM threshold I-05's `TtlPolicy` already uses. Toggleable via `Settings.ENABLE_BATTERY_AWARENESS` (default on -- a genuine no-op on any desktop). Thermal throttling detection (the plan's "& Thermal" half) is deferred -- no reliable cross-platform signal exists via `psutil` alone; named as follow-up work, not fabricated.
- **Community Capability Database (I-12).** `app/registry/community_scores.py` -- `CommunityScoreLoader` reads a static, checked-in `configs/community_scores/snapshot.json` (ships empty; no fabricated scores). `ModelScorer`'s benchmark factor now falls back to a matching-hardware-tier community entry (provenance `COMMUNITY`) only when this machine has no local `MEASURED` result for that model -- a local measurement always wins, never the reverse. The tier used for lookup comes from whatever `lair doctor --init` last recorded (`configs/active_portfolio.yaml`), not re-derived per request, since GPU detection is deliberately not run on the routing hot path (`LocalHardwareProvider` always reports VRAM as unknown). `export_contribution()` / `lair community export --tier <tier>` produces a shareable, anonymized JSON export of this machine's own benchmarks -- model id, hardware tier, and tokens/sec only, never the benchmark prompt.
- **Voice Interface (I-11).** `app/voice/` -- `SpeechToText` (`faster-whisper`) and `TextToSpeech` (`kokoro-onnx`), both lazily loaded and both optional: neither package is in `requirements.txt`; install `requirements-voice.txt` to enable. `POST /v1/audio/transcriptions` / `POST /v1/audio/speech` (OpenAI-compatible shapes) return a `503` with an actionable install/config message when the extra (or, for TTS, the locally-downloaded `model.onnx`/`voices.bin` pair Kokoro requires -- it does not auto-fetch weights the way I-08's embedding model does) isn't present, never a crash. `lair voice --input in.wav --output out.wav [--project-scope ...]` is a file-based round trip (transcribe -> normal `/v1/chat/completions`, so I-10 language routing and I-18 memory apply unchanged -> synthesize reply), deliberately not a live microphone loop -- real-time audio I/O and wake-word support (OpenWakeWord) are named, honestly deferred future work, not built speculatively. Whisper's own detected language picks the TTS reply's locale (`app/voice/language_map.py`). No live-hardware round-trip latency benchmark was run this pass (would need real model-weight downloads); the plumbing is verified via injected fakes plus one real (unmocked) test of the dependency-missing 503 path.
- **Persistent Project Memory (I-18, RFC-0002, ADR-0020).** `app/memory/` -- durable, per-project-scope memory reusing I-08's `EmbeddingModel` and JSON-backed-store idiom rather than the plan's suggested SQLite. A heuristic extractor (`extraction.py`) spots durable statements ("remember...", "I prefer...", "always/never...") in a user's message; `MemoryStore.remember()` dedupes near-identical memories within the same project scope by embedding cosine similarity (>= 0.92 merges, doesn't duplicate). `ChatCompletionRequest.lair_project_scope` opts a request into retrieval + extraction; `lair_meta.memory_injected_count` reports usage (provenance `MEMORY`, reserved by I-13). `lair memory list/show/forget/export` CLI gives full local read/delete/export access. Off by default (`Settings.ENABLE_PROJECT_MEMORY`); disabled behavior is byte-identical to pre-I-18 LAIR.

### Changed

- Refactored `BaseProvider` to return `AIModel` objects instead of raw dictionaries.
- Refactored LM Studio provider to use the domain model.
- Refactored `ModelRegistry` to use the new `ProviderRegistry`.
- Expanded application configuration for future providers and routing.
- **Breaking:** `/route` response is now plan-shaped (`plan.steps`, `plan.decision`) instead of a flat `selected_model`/`provider`/`confidence`/`breakdown` body.
- Capability scoring now reads weights from `RoutingPolicy.capability_weights` instead of the standalone `CAPABILITY_WEIGHTS` constant and `Settings` fields — same values, single source of truth, not a scoring regression.
- `CapabilityResolver`/`ResourceResolver` now ground VISION/EMBEDDING/TOOL_USE/`context_window`/resource estimates in real LM Studio metadata when available, falling back to the original heuristics otherwise — REASONING/CODING/TRANSLATION/SUMMARIZATION remain heuristic (no data source exists for them).
- `AIModel.loaded` now reflects the provider's real reported state instead of always being hardcoded `True`.
- **Not-loaded models are no longer excluded from routing candidates.** `RoutingEngine.route()` dropped its hard `if model.loaded` filter (added in Milestone 5) in favor of a soft `loaded_bonus_score` in `ModelScorer` (`RoutingPolicy.loaded_bonus_weight`, default `5.0`) — an already-loaded model is preferred when candidates are otherwise close, but a better-suited unloaded model can still be selected and trigger LM Studio's JIT loading. Justified by live dogfooding (`docs/DOGFOODING.md`, DF-006) confirming JIT loading + Auto-Evict reliably handles the load/swap, and by Milestone 6's graceful failure handling superseding the original bare-400 justification (ADR-0013 update).
- `filter_by_hardware()` now checks an unloaded candidate's estimated RAM against available RAM *plus* whatever RAM currently-loaded models would release on eviction, instead of available RAM alone — otherwise a valid model swap would still be wrongly rejected as "won't fit."
- **Capability matching is no longer a hard filter in `RoutingEngine.route()`.** Previously a model had to satisfy *every* keyword-detected requirement simultaneously (`CapabilityEngine.find_matching_profiles()`'s AND semantics) to be a candidate at all; a longer, richer real message (e.g. one touching coding, translation, and vision at once) could trigger multiple requirements that no single small local model satisfies together, correctly-but-uselessly excluding every model and returning 404. `RoutingEngine.route()` now passes all models through as candidates and relies entirely on `ModelScorer`'s existing per-requirement scoring to prefer the best match — `CapabilityEngine.find_matching_profiles()` itself is unchanged and keeps its own AND-matching contract for other callers.
- **Breaking (internal):** `BaseProvider.complete()` now takes `messages: list[dict]` instead of a flat `prompt: str` — preserves full multi-turn conversation context through to the provider instead of collapsing it into a single message. Touches `LMStudioProvider`, `BenchmarkRunner`'s call site, and `FakeProvider`.
- `RoutingEngine.route()` no longer persists — it dropped its `decision_repository` parameter and the `DecisionRepository.record()` call, becoming a pure computation (analyze → filter → score → select → return). Persistence now happens explicitly in the API handlers (`app/api/routing.py`, `app/api/chat.py`) that call it.

### Fixed

- `ChatMessage.content` now accepts the OpenAI-valid list-of-parts shape (`[{"type": "text", "text": "..."}]`), not just a plain string — Cline sends messages this way, and `/v1/chat/completions` rejected every request from it with a `422` until this normalized at the schema boundary. Non-text parts (e.g. images) are dropped; providers don't accept multimodal input yet. Found live via the DF-002 dogfooding experiment (`docs/DOGFOODING.md`).
- `/route` no longer crashes with a `ValidationError` (the selector built a `RoutingDecision` with fields, `score`/`reasons`, that didn't exist on the class).
- `requirements.txt` was UTF-16 encoded, breaking `pip install` on most environments; re-saved as UTF-8.
- `KnowledgeBase` no longer crashes `/route` when a stored benchmark record predates a `BenchmarkResult` schema change (e.g. the new `run_id` field) — unreadable records are now skipped and logged instead of raising.
- `/route` no longer mislabels unrelated validation errors as "no suitable model found" — it caught bare `ValueError`, which `pydantic.ValidationError` subclasses; now catches the specific `NoCandidateModelsError` it's meant to.
- `CapabilityProfile.context_window` had been `None` for every model since Milestone 1 (nothing ever set it), meaning `ModelScorer.context_window_score` silently contributed `0.0` to every routing decision — now populated from real provider metadata when available.
- `filter_by_hardware()` was checking an already-loaded model's estimated memory requirement against currently-*free* RAM, wrongly excluding it — a loaded model's memory is already allocated and it's proven to be running right now, so the RAM-fit check only makes sense for a model that would need fresh allocation to load. Surfaced live only once real loaded-state data existed (this milestone); already-loaded models are now always kept.

### Removed

- `app/router/` — empty, unused duplicate of `app/routing/`.
- `app/routing/capability_weights.py` — migrated into `RoutingPolicy` defaults.
- `Settings.STREAMING_WEIGHT` / `CAPABILITY_WEIGHT` / `CONTEXT_WINDOW_WEIGHT` — migrated into `RoutingPolicy`.
